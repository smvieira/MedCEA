# apps/superset/requirements.txt — the three packages apache/superset:6.1.0 (lean) lacks.
# Downloaded once into the host's wheel cache SUPERSET_WHEEL_DIR by the full deploy
# (Job superset-wheels: pip download --require-hashes --only-binary=:all:, owner decision
# N10), then installed at every pod start by the init container superset-deps
# (k8s/superset.yaml, k8s/superset-init.yaml) from that folder alone with
#   pip install --isolated --no-deps --require-hashes --only-binary=:all: --no-index
#               --find-links /wheels --target /opt/extra
# so every line pins one wheel by sha256 and nothing else is pulled in. The image's
# Python is 3.10.21 (image config of the pinned digest, not the 6.1.0 Dockerfile's
# default 3.11): every wheel must be cp310 or py3-none-any, and joserfc 1.8.0 (Python
# >= 3.11) does not install. Hashes read from PyPI's JSON on 6 Nov 2026.
#
# Authlib: FAB 5.0.2's OAuth path (Authlib >=0.14,<2.0). 1.9.5, not 1.6.x: the October
#   2026 advisories (JWS empty signature, empty HMAC key, algorithm confusion, the ID
#   token nonce bypass) are fixed only in 1.9.0/1.9.1. Needs joserfc >= 1.6.8 and
#   cryptography >= 45.0.1 (the image has 46.0.5).
# joserfc: 1.7.7, the newest for Python 3.10 (past the joserfc 1.7.5/1.7.6 fixes).
# psycopg2-binary: 2.9.9, the version Superset 6.1.0's own `postgres` extra pins.
#
# To move a pin: read https://pypi.org/pypi/<name>/<version>/json, take the sha256 of
# the cp310 manylinux x86_64 (or py3-none-any) wheel, replace both, re-run
# python3 tests/test_superset_render.py, then ./apps/superset/deploy.sh (it downloads
# the new wheel into the cache; the old one may stay, nothing installs it).
