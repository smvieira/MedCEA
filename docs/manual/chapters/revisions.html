1115 Nov 202632f0264 + this edition, branch recipe-types (not deployed yet)Recipe types. A recipe has a recipe type, Plants or Fungi, a master template that lists the quantities its steps set; each step keeps its photoperiod and gives each quantity a lower and an upper limit (its setpoints), required ones on every step, so a new controlled value is a line in one file (apps/database/recipe_types.yaml), not a change to tables, forms and the runner (migration 011). A unit's type is its recipe type (Greens became Plants, Mushrooms Fungi), and a recipe runs only on units of its type. Recipe files are format 2; older files are imported with the type asked. The Run Monitor's substrate gauge now shows its limits. A zone's control loops are bound board by board, in either order: the SENSE board's onboarding chooses the sensor and reading of each quantity (any reading in the quantity's unit), the CONTROL board's the actuator, which can declare its quantity in the channel map; a half-bound loop runs on the default map's other half meanwhile, and the health check counts it. One policy version (6, the catalogue for the runner). New sections Recipe types, recipes and setpoints and Recipe types and the quantity catalogue; decision record rows of 15 November 2026; exercises E37 and E38, not yet run.
1013 Nov 202620eae25 + this edition, branch feedback/p1-p2 (not deployed yet)Feedback control Phases 1 and 2. Changes are refused while the unit has a run running or scheduled. The policy ships as two skeleton versions (2a, the table for the runner; 2c, the engineer's two functions).
